\section*{Annotation}
\addcontentsline{toc}{section}{Annotation}
Internet memes are now one of the most common forms of communication online. However, searching for the perfect meme is far from trivial. Traditional search engines consider memes as just images, overlooking rich semantics: superimposed text, cultural references, and nuanced humour.

This work introduces a multimodal meme search engine, implemented as a Telegram bot. Users can search by text query in English or Russian, by a reference image, or by both modalities. Each meme is annotated by gpt-5.4-mini-fast with vision, which auto-generates 10 structured fields. The dataset includes 16,030 memes collected from 6 sources. Annotations are indexed using multilingual BGE-M3 embeddings into three FAISS indices; results are combined with Reciprocal Rank Fusion, and output diversity is ensured by Maximal Marginal Relevance.

Evaluation on a test set of 100 memes (495 queries) shows that the system achieves Hit@5 = 60.0\% for English and 57.0\% for Russian queries, outperforming the baseline by 28 and 55 percentage points, respectively.

\section*{Keywords}
Multimodal retrieval, semantic search, hybrid search, VQA, vision-language models, BGE-M3, FAISS, RRF, MMR, OCR, multilingual retrieval, perceptual hashing.

\section{Introduction}

Internet memes have become a universal language in the age of the internet. Every day millions of memes are created by people all over the world. They are useful for adding cultural context, humor, personality, and commentary to a message in a way that is unique to memes. Memes are used in every aspect of online communication. People use them in personal conversations, advertising, and marketing among countless other applications.

Current image search technologies fail to address the needs of those who wish to work with memes. Keyword or visually similar search does not scale to the particular needs of memes. Image search engines lack the capacity to understand multimodal content with both visual and textual elements. A meme often contains hidden meaning that cannot be derived directly from the visual content or text separately; understanding a meme requires joint analysis of the image and overlaid text. Meme interpretation also requires knowledge of cultural references, internet trends, and the specifics of online communities, as the same template can be used to express completely different messages. Finally, formats range from simple images with text to complex montage and comics, which complicates the application of unified processing methods. The emergence of advanced Vision-Language Models opens new opportunities for solving the meme retrieval task. Unlike earlier approaches that depend on simple image-text alignment, modern VLMs can extract overlaid text, identify visual objects, and interpret the underlying humor or cultural context, providing a rich semantic representation for complex multimodal search.

The goal of this project is to develop an intelligent multimodal meme retrieval service, implemented as a Telegram bot with a backend system, that allows users to find relevant memes by text description, reference image, or their combination. To achieve this goal, a database of approximately 16,000 memes from open sources was collected and prepared, including text extraction from images (OCR) and semantic description generation using gpt-5.4-mini-fast with 10 structured annotation fields. A multimodal index was built on top of vector embeddings (BGE-M3) with efficient storage and search in FAISS. A hybrid retrieval architecture with Reciprocal Rank Fusion across multiple indices and Maximal Marginal Relevance for diversity was implemented. A Telegram bot supporting three input modes (text, image, hybrid) with a user-friendly interface and automatic database updates was developed. Finally, the system was evaluated using standard information retrieval metrics (Hit@K, MRR) on a test set developed through a mixed approach of manual annotation and LLM-as-a-Judge evaluation.

The real-world impact of this project comes from applying multimodal meme retrieval to production. This pipeline has been deployed as a Telegram bot, showcasing an end-to-end implementation of Vision-Language Models that can be used in everyday communication. The indexing pipeline described in this work enables efficient retrieval of culturally rich memes via LLM-generated VQA annotations paired with hybrid vector search, and shows substantial gains over semantic baselines.

The novelty of this project lies in its comprehensive approach to multimodal meme retrieval. First, it uses VQA annotations rather than simple captions: gpt-5.4-mini-fast with vision generates structured 10-field meme descriptions that account for visual content, overlaid text, semantics, emotions, and search queries, capturing deeper semantic information than caption-only baselines. Second, the retrieval architecture combines early fusion, where all annotation fields are concatenated into a single mega-text before encoding, with late fusion, where multiple FAISS indices are searched independently and their rankings are merged via Reciprocal Rank Fusion; Maximal Marginal Relevance is then applied to ensure diversity in the final ranking. Third, perceptual hashing with phash is used to detect cross-source duplicates, which are filtered at retrieval time while preserving index position consistency. Finally, the approach is specialised for the meme domain, adapting retrieval techniques to the specifics of internet memes --- overlaid text, cultural references, and semantic complexity --- which differ substantially from generic images.

The remainder of the report is organized as follows. Section~\ref{sec:relatedwork} reviews the literature on multimodal retrieval, vision-language models, and meme semantics, and presents a functional comparison with existing meme search solutions. Section~\ref{sec:methods} describes the proposed system: the construction of a multilingual meme corpus with semantic annotation via vision-language models, a multi-index retrieval architecture with late fusion, the evaluation protocol with LLM-as-a-Judge, and component ablations. The report concludes with a summary of contributions and directions for future work.

\section{Theoretical foundations of multimodal search and meme semantics}
\label{sec:relatedwork}

\subsection{A review of multimodal retrieval, vision-language models, and meme semantics}

Drawing upon the existing literature on multimodal image retrieval, five major trends can be distinguished: shared embedding space, vision-language model-based captioning, meme understanding as a separate task, vector search methods, and hybrid retrieval with diversity-aware re-ranking.

Building a shared embedding space for images and text was pioneered by the CLIP multimodal learning model introduced in the paper by \href{https://arxiv.org/abs/2103.00020}{Radford et al. (2021)}~\cite{radford2021clip}. Authors pretrained a pair of neural network encoders on a corpus of 400 million text-image pairs scraped from the internet. The trained model projects data points into a shared vector space where embeddings of contextually related texts and images are situated close to one another. As such, search over images and text can be performed using cosine similarity. However, CLIP was pretrained on generic images and ignores memes' specificities - added text, cultural references, multi-layered jokes.

Vision-language models have also been successfully applied to caption images with text. Developed by \href{https://arxiv.org/abs/2301.12597}{Li et al. (2023)}~\cite{li2023blip2}, BLIP-2 utilizes Q-Former architecture to efficiently couple frozen vision encoders with powerful large language models. It matches SOTA results on VQA and image captioning tasks while requiring 10-100x less computational resources. Alternative approach is taken by \href{https://arxiv.org/abs/2304.08485}{Liu et al. (2023)}~\cite{liu2023llava} who train LLaVA model to follow natural language instructions while working with images. This paves way for posing flexible queries to images to extract arbitrary information. Closed-source industrial-grade VLMs such as GPT-4V~\cite{openai2023gpt4v} build on top of this idea with orders of magnitude better annotation quality. Said model was used in this project to generate VQA annotations - structured descriptions of memes.

Multimodal meme understanding is tackled in several recent papers. Dataset of 10k memes titled Hateful Memes Challenge was introduced in the paper by \href{https://arxiv.org/abs/2005.04790}{Kiela et al. (2020)}~\cite{kiela2020hateful}. It was constructed in a way that even using both text and image would not allow one to reliably predict if the meme is offensive or not. Empirical results indicate that multimodal approaches (accuracy 64.7\%) significantly outperform unimodal ones (59.2\% for text only, 52.6\% for image only), illustrating joint modality analysis importance. Roy et al.~\cite{roy2024mememqa} expand on previous idea by introducing MemeMQA dataset which allows users to interact with memes using questions. Said work also does not consider retrieval.

Several state-of-the-art multilingual text encoders are available which expand upon Sentence-BERT~\cite{reimers2019sbert} foundation for dense semantic search. Modern solutions such as BGE-M3~\cite{chen2024bge} work with over 100 languages and generate dense embeddings that are well-suited for nearest-neighbour search. BGE-M3 was chosen as production encoder for this project after comparing publicly available multilingual baselines.

Performing nearest-neighbour search over dense embeddings at scale requires specialized vector search indices. Developed by \href{https://arxiv.org/abs/2401.08281}{Douze et al. (2024)}~\cite{douze2024faiss}, FAISS library features highly optimized implementations of IVF and Product Quantization algorithms and can perform billion-scale searches in sub-millisecond time. Hierarchical Navigable Small World graph (HNSW) proposed by \href{https://arxiv.org/abs/1603.09320}{Malkov \& Yashunin (2020)}~\cite{malkov2020hnsw} ensures logarithmic search complexity using clever graph data structure.

Hybrid search combining multiple ranking signals has been shown to be effective in modern information retrieval pipelines. BM25~\cite{robertson2009bm25} continues to be the go-to sparse retriever, effectively capturing exact term matches frequently missed by neural networks. Comparative analysis of sparse vs dense representations was done by \href{https://aclanthology.org/2021.tacl-1.20/}{Luan et al. (2021)}~\cite{luan2021sparse}. Their experiments show that incorporating both yields 5-8\% improvements over individual approaches on MRR@10 metric. To combine rankings produced by heterogeneous retrievers with minimal overhead, Reciprocal Rank Fusion ~\cite{cormack2009rrf} has become de-facto standard technique. Maximal Marginal Relevance ~\cite{carbonell1998mmr} is a classic diversification re-ranking criterion that enforces trade-off between relevance and redundancy with respect to previously chosen items. Both aforementioned techniques are core parts of proposed system. Late interaction cross-encoder paradigm pioneered by \href{https://arxiv.org/abs/2004.12832}{Khattab \& Zaharia (2020)}~\cite{khattab2020colbert} allows achieving cross-encoder quality at 170x speedup using ColBERT model.

Extracting text from memes requires using Optical Character Recognition software. Detailed benchmark for state-of-the-art OCR models was published by \href{https://arxiv.org/abs/2009.09941}{Du et al. (2020)}~\cite{du2020ppocr}. PaddleOCR system described in their work reaches 90.3\% accuracy on text detection benchmark while running 10x faster than Tesseract on photos with mixed backgrounds. EasyOCR library~\cite{jaidedai2020easyocr} serves as complementary, first-stage OCR engine in pipeline used by this project. De-duplicating datasets using image embeddings introduces near-duplicates. Perceptual hashing~\cite{zauner2010phash} allows constructing compact fingerprint of image, well-suited for fuzzy duplicate detection across multiple datasets.

In conclusion, existing image search solutions struggle with multimodal nature of memes. Scientific interest in multimodal memes understanding exists but focuses on classification task. This project brings together recent advances in multimodal embeddings, vision-language models-based VQA annotation, hybrid search, and result re-ranking into end-to-end solution for the task of meme retrieval.

Google Lens (formerly Google Reverse Image Search) operates primarily on visual similarity and is designed for finding the source of a specific image rather than discovering thematically related memes from a description. Bing Images. Images are queried using a custom scraper that rotates query strings across 60 search terms spanning common meme genres, downloading images in parallel and performing de-duplication by URL hash. This provides the widest coverage of thematic variance, as any website frequently referenced in meme communities is likely to be indexed by search.

Telegram Stickers. Approximately 100 publicly available sticker packs were scraped through Telegram Bot API. Packs were selected to roughly fulfill two parameters: popularity - sticker packs featuring widely recognizable meme characters/templates, or otherwise popular Russian sticker collections; content safety - Telegram sticker packs are moderated by Telegram staff members, therefore unlikely to contain obscene/graphic imagery. This decreases the necessity of heavy downstream filtering. Stickers were downloaded as static WebP files through the Bot API then transformed into PNG format. Animated stickers/stickers bundled with video were excluded.

Kaggle Memotion. This dataset from a Kaggle competition consists of 7k hand-labeled memes with sentiment analysis annotations. It was included to ensure coverage of more traditional meme styles.

Kaggle Russian Memes. This small dataset supplements coverage of memes with Cyrillic text.

HuggingFace Datasets and Imgflip. Included to help support more template diversity. Imgflip's data contains many canonical templates that can help ground template recognition during the VQA stage.

Incremental updates to the dataset are supported by the system. Images dropped into an incoming directory are periodically detected by a background job and pushed through the entire annotation workflow: the VLM generates structured annotations, search queries are translated into Russian, then those texts are encoded with bge-m3. The resulting vectors are appended to the live FAISS indices without having to rebuild them from scratch. Cluster-based rotation kicks in when the size limit is reached, the oldest entries get dropped in a weighted fashion across tag-derived splits to avoid distribution drift and maintain genre ratios. In the deployed system, the incoming directory is populated automatically by a background scraper that polls nine popular meme communities on Reddit every 30 minutes, selected to maximise genre coverage across general, niche, and tonally diverse content. Posts are filtered by upvote score, image dimensions, and perceptual hash similarity before being placed into the incoming directory for annotation.

\textbf{OCR Pipeline.} Text extraction from meme images is performed in two stages. The first pass employs EasyOCR~\cite{jaidedai2020easyocr} with Russian and English language models to extract recognized text segments and their confidence levels. Images surviving the first round of cleaning are then processed by PaddleOCR v3~\cite{du2020ppocr}, which uses the DB text detector and CRNN-based recognizer with Russian language support. Images are read via OpenCV to handle all formats including WebP and PNG. Both OCR engines are run sequentially during initial dataset construction: EasyOCR serves as a fast initial quality gate, eliminating corrupt files, blank images, and entries without detectable text, while PaddleOCR performs the final text extraction on the surviving subset. In the auto-update pipeline a separate OCR step is not required: the VLM annotation model extracts overlaid text directly as part of the structured annotation, populating the \texttt{ocr\_text} field alongside all other metadata in a single inference call. The 0.6 confidence threshold was selected empirically after manual inspection of a sample of PaddleOCR outputs across all sources. At confidence $\geq 0.6$, outputs were found to be usable as-is in the majority of spot-checked cases. Below that threshold, character substitutions, merged words, and spurious characters were observed with increasing frequency.

\textbf{Data Cleaning and Filtering.} The cleaning pipeline operates in two passes with different filter configurations.

The first pass performs content-based and text quality filtering. A hand-written list of over 640 prohibited words and phrases in Russian and English is matched via exact substring search, followed by a fuzzy matching step using the Levenshtein distance (similarity threshold of 85\%, tuned to catch common obfuscation patterns while avoiding false positives on short words). Text length is also constrained to a minimum of 3 and a maximum of 400 characters.

In the second pass, the cleaned results from all data sources are merged into a single dataset. Entries whose OCR text is longer than 2 characters but has a confidence score below 0.6 are removed; entries with a confidence of 0 (no text detected) or $\geq 0.6$ are retained. A second pass of prohibited-word filtering by exact substring matching is then applied.

It should be noted that OCR confidence scores measure recognition quality for a given character sequence, not whether text is actually present in the image. A confidence of 0 may indicate that the recognition algorithm failed rather than that the image contains no text. Proper calibration of such a threshold would require a labelled dataset of 200-500 manually annotated memes with ground-truth transcriptions, evaluated by CER, WER, and precision/recall.

\textbf{Final Dataset.} After merging PaddleOCR results and applying all filters, the final dataset contains 16,080 entries from the 18,936 raw images. The difference of 2,856 images is accounted for as follows: 539 images were removed by the content moderation filter, while the remaining losses are due to corrupt or unreadable files, images with no detectable text regions, format incompatibilities that prevented PaddleOCR from producing an output file, and entries removed by the confidence filter. The first prototype used Qwen2.5-VL-3B executed locally via Ollama. This setup annotated ~10k memes in two passes. The base pass generated 6 fields per image (\texttt{caption}, \texttt{ocr\_text}, \texttt{meme\_template}, \texttt{objects}, \texttt{tone}, \texttt{main\_idea}), after which a separate enrichment pass generated another 5 fields (\texttt{ocr\_normalized}, \texttt{objects\_detailed}, \texttt{relations}, \texttt{required\_context}, \texttt{vqa}). Completion times with two passes ranged from 18-22 hours total on Apple M4 Pro. The hallucination rate was ~3.3\%. A comparison batch of 100 validation memes was run through Qwen3.5-9B, which showed that scaling up the model does help with description quality: caption length went up 2$\times$, OCR detection increased from 37\% to 65\% of images, and correctly detecting meme templates rose to 18\%. Throughput is bottlenecked by single-GPU execution.

For the final annotation run, GPT-5.4-mini-fast with vision was used via an OpenAI-compatible API endpoint. The key difference with this setup was that this model was able to generate all 10 fields with a single prompt, which allowed for nearly-complete field coverage across all fields: 100\% for \texttt{caption}, \texttt{objects}, \texttt{tone}, \texttt{main\_idea}, \texttt{search\_queries}, \texttt{tags}, and \texttt{emotions}; 77.7\% for \texttt{ocr\_text}; and 26.2\% for \texttt{meme\_template}. Parallelized across 5 workers, annotating all 16k memes took just under an hour. This represents a 10-20$\times$ speedup relative to the local Qwen pipeline. Overall, moving from MiniLM embeddings over Qwen captions to bge-m3 over GPT annotations improved EN Hit@5 from 32\% to 47\% and RU Hit@5 from 2\% to 45\%. From the 16,080 cleaned entries, all images were selected for VQA annotation; no subset sampling was required due to the efficiency of the GPT-based pipeline. The final annotated corpus contains 16,030 memes, as 50 images were skipped due to file corruption or format issues.

\textbf{Annotation Schema.} The annotation script processes each meme image through GPT-5.4-mini-fast and produces a complete annotation in JSON format with the following 10 fields:

1. \texttt{caption} - 2-3 sentence neutral description of the image content.

2. \texttt{ocr\_text} - exact text extracted from the image by the VLM, preserving the original language and punctuation.

3. \texttt{meme\_template} - name of the recognized meme template if detected.

4. \texttt{objects} - list of 5-10 key visual elements.

5. \texttt{tone} - emotional tone classification: ironic, wholesome, absurd, dark, relatable, aggressive, or neutral.

6. \texttt{main\_idea} - one sentence summarizing the joke or main message.

7. \texttt{search\_queries} - 3-5 short phrases a user would type to find this meme. This field was added heuristically: early experiments showed that caption-only embeddings performed poorly on both English and Russian queries because users word their searches differently from how captions describe images. The idea was that indexing model-generated search queries separately would bridge this gap. In the final system, search\_queries feed into 2 English indices and, after translation, into 3 Russian indices.

8. \texttt{tags} - 5-10 descriptive keyword tags.

9. \texttt{emotions} - list of emotions conveyed by the meme.

10. \texttt{vqa} - 6 question-answer pairs covering text content, visual description, scene interpretation, joke explanation, target audience, and a one-sentence search description.

Images are resized to 512px maximum dimension and converted to JPEG before encoding to base64. The model is queried with \texttt{temperature=0.2} and a 1000-token generation limit. The exact prompt is shown in Figure~\ref{fig:annotation_prompt}.

\textbf{Pipeline Implementation.} The script supports resume functionality: it tracks already-processed filenames and skips them on restart. Processing is parallelized across multiple threads to reduce annotation time. JSON response parsing includes robust handling of markdown code blocks and truncated responses. All annotations are stored in JSONL format, with one JSON object per line. Each record contains 18 keys in total: the 10 annotation fields described above plus 8 metadata fields: \texttt{filename}, \texttt{source\_path}, \texttt{confidence}, \texttt{source\_type}, \texttt{is\_nsfw}, \texttt{nsfw\_reason}, \texttt{is\_duplicate}, and \texttt{search\_queries\_ru}, which stores Russian translations of search queries.

Baseline \texttt{all-MiniLM-L6-v2} gives 32\% Hit@5 on English, but only 2\% Hit@5 on Russian, making it essentially unusable for cross-lingual retrieval. Model \texttt{sbert\_large\_nlu\_ru}, trained on Russian language NLU dataset from Sberbank AI, shows poor performance at 3\% Hit@5 on Russian and 6\% Hit@5 on English, highlighting that models trained for NLI perform poorly when repurposed for semantic search. Production model \texttt{BAAI/bge-m3}~\cite{chen2024bge} also outputs 1024-dimensional normalized vectors, and spans over 100+ languages. Although \texttt{multilingual-e5-large} achieves the best score on English (43\%), it significantly decreases to 28\% on Russian. Although fine-tuned version \texttt{deepvk/USER-bge-m3} gives slightly better results on English than base model (40\% vs 38\%), fine-tuning hurts performance on Russian. Original bge-m3 model was chosen because it was the only model with scores above 35\% on both languages.

\paragraph{CLIP image embeddings.} A third index in RRF based on image embeddings from CLIP was also tested. Adding CLIP improved English Hit@10 by +3.2 pp, but decreased Russian Hit@5 by $-$2.1 pp (57.0\% $\to$ 54.9\%), as CLIP's text encoder is English-only and cannot match Russian queries to image features. The trade-off was deemed too skewed, and the image index was not used in production.

\paragraph{BM25 sparse retrieval.} Sparse keyword matching with BM25 was considered as another retrieval signal. BM25 helped improve English Hit@5 from 39\% to 41\% when combined with dense retrieval, but did not help with cross-lingual queries since there is no lexical overlap between Russian terms and English annotations. bge-m3 has native support for dense+sparse hybrid retrieval, however sparse features did not help when annotations are just English text.

\textbf{Index Construction.} For fast nearest-neighbour search, FAISS~\cite{douze2024faiss} indices of type \texttt{IndexFlatIP} are built. Inner product on L2-normalised vectors is equivalent to cosine similarity. Brute-force search over 15,530 vectors of 1024 dimensions takes less than 5 ms per query, so approximate methods such as HNSW or IVF are not beneficial at this scale and only pay off above approximately 100k vectors. Three indices are constructed:

\begin{enumerate}
    \item \texttt{faiss\_all\_fields.index}: all 10 annotation fields concatenated into a single mega-text before encoding.
    \item \texttt{faiss\_en\_search\_queries.index}: English search queries only.
    \item \texttt{faiss\_ru\_search\_queries.index}: Russian-translated search queries.
\end{enumerate}

The mega-text approach, where all fields are concatenated before the text encoder, proved superior to a late fusion baseline that maintains one index per field group and merges results with RRF. A single mega-text index achieves 61\% Hit@5 on English, while late fusion with 4 separate indices and RRF scores 56.4\% - a 4.6 pp difference. The single-index approach offers higher performance as well as simpler architecture and lower memory requirements. All indices contain 15,530 vectors, derived from 16,030 annotations after removing 500 NSFW-flagged entries at index construction time. Duplicates - 5,827 entries flagged by perceptual hashing - are left in the index and filtered at search time without affecting embedding space coverage. A metadata JSONL file maps index positions to filenames, source paths, and all annotation fields.

\textbf{Search Modes.} The system supports three search modes:

\begin{enumerate}
    \item Search by text. The query is encoded with bge-m3 and searched against several indices. For English queries, two indices are searched - mega-text and English search queries - with RRF weights 0.6 and 0.4. For Russian queries, detected automatically by the presence of Cyrillic characters, all three indices are searched with RRF weights 0.4, 0.3, 0.3. The result list is then filtered with MMR, which removes items with cosine similarity above 0.80 to already-selected results, ensuring diversity.

    \item Search by image. The user uploads a reference image. The image is sent to GPT-5.4-mini-fast, which generates a text description. This description is then used as a query from item~1 to produce results based on image semantics, without needing a separate image embedding index.

    \item Hybrid search. The user uploads an image together with a text caption. The text and image parts are processed separately as in items~1 and~2. The two result lists are then merged using a second-level RRF with weights 0.6 for text and 0.4 for image, followed by MMR diversification.
\end{enumerate}

\textbf{Application Layer.} The user-facing application is a Telegram bot implemented in aiogram~3 framework, as illustrated in Figure~\ref{fig:architecture}. At startup, it loads 3 FAISS indices, the BGE-M3 model and all meme metadata. Supported functionalities include English and Russian text queries, image-based search, hybrid search using an image and a text query, and paginated responses (5 memes per page, 25 results in total). A background task runs every 5 minutes that scans for newly added memes. For each new meme, it runs the annotation pipeline, which consists of gpt-5.4-mini-fast annotation followed by Russian translation and bge-m3 encoding. New vectors are appended to the live indices without the need to restart the bot. The meme database is periodically culled when it reaches a configurable threshold. Old memes are dropped from the indices in a cluster-wise rotation such that memes are evenly culled from each tag category. This avoids distribution drift that would otherwise result from uneven growth in the tag categories.

Uploaded images are passed to gpt-5.4-mini-fast with vision to generate text captions, which are then used as search queries. After FAISS returns the result set, perceptual hashing with 256-bit phash is applied to filter out the uploaded image itself and near-duplicates from the results.

\subsection{Evaluation protocol with LLM-as-a-judge and final retrieval performance}

Retrieval quality is evaluated on a held-out test set of 100 memes sampled uniformly at random from the full dataset. For each meme, 5 search queries are generated in English and 5 are generated in Russian. This results in a total of 1,000 candidate queries across both languages. 1 of the 100 test memes was marked NSFW and removed from the search index entirely. This results in effective evaluation on 99 memes and 495 queries per language.

\textbf{Query Generation.} For each of the 100 test memes, one English and one Russian search query were authored manually by the project developer based on the meme's visual content, caption, and cultural context. These seed queries served as structural examples for the LLM, which then generated 4 additional queries per language, bringing the total to 5 per meme per language. Each set of 5 queries covers a range from highly specific, such as the meme template name, to general, such as the emotional tone or situation depicted. Russian queries are independent formulations rather than word-for-word copies of the English ones, reflecting how a native speaker would naturally search for the same meme.

\textbf{LLM-as-a-Judge Evaluation.} Each set of 5 queries was evaluated by gpt-5.4-mini-fast acting as an automated judge. The judge receives the meme image, its VQA annotation (caption, OCR text, main idea), and the full query set. It scores the query set on four dimensions using a 1 to 5 scale:
\begin{enumerate}
    \item \textbf{Relevance}: how well each individual query matches the target meme, scored per query and averaged.
    \item \textbf{Diversity}: whether the 5 queries cover different search strategies (textual, visual, emotional, situational) rather than repeating the same idea.
    \item \textbf{Naturalness}: whether the queries read like real user searches rather than formal descriptions.
    \item \textbf{Specificity balance}: whether the set includes both narrow queries (e.g. meme template name) and broad queries (e.g. emotional tone).
\end{enumerate}

In addition, two binary flags are checked: \textbf{hallucination} (a query references content not present in the meme) and \textbf{duplicate} (two queries are semantically identical). The final quality score is computed as a weighted combination:
\begin{equation}
\label{eq:judge_score}
\text{score} = 0.4 \cdot \text{relevance} + 0.3 \cdot \text{diversity} + 0.15 \cdot \text{naturalness} + 0.15 \cdot \text{specificity}
\end{equation}

\textbf{Retrieval Metrics.} Retrieval quality is measured using standard information retrieval metrics:
\begin{enumerate}
    \item \textbf{Hit@K}: the fraction of queries for which the target meme appears in the top-$K$ retrieved results. Hit@1, Hit@5, and Hit@10 are reported.
    \item \textbf{MRR@10} (Mean Reciprocal Rank): for each query, the reciprocal of the rank at which the target meme first appears within the top 10 results, averaged over all queries. If the target is not found in the top 10, the reciprocal rank is 0.
\end{enumerate}

For each query, the system encodes the query text with bge-m3, searches multiple FAISS indices, fuses results using RRF, and checks whether the known target meme index appears in the ranked list.

English queries obtain a higher score than Russian queries on both relevance and satisfaction, which is not surprising as the corpus is overwhelmingly in English. The similarity of the diversity scores across languages indicates that the MMR re-ranking step provides effective result diversification regardless of query language.

\subsection{Component ablations and the role of Russian indexing in cross-lingual performance}

\textbf{NSFW Filtering.} To ensure content safety, a vocabulary-based NSFW filter was applied to all textual fields of each meme annotation using two matching strategies:

\begin{enumerate}
    \item Exact word match: text is tokenised into words and checked for membership in a curated stop-word set.
    \item Prefix matching: words that begin with known offensive morphological roots are flagged, catching inflected forms without explicit enumeration.
\end{enumerate}

The stop-word dictionary contains more than 640 terms covering Russian and English profanity, transliterated forms, and digit-substituted variants. Text is normalised to lowercase with \foreignlanguage{russian}{ё} to е substitution before matching. Of the 16,030 annotated memes, 3.1\% were flagged as NSFW. These records are retained in the annotation file but excluded from search results at retrieval time.

\textbf{Deduplication.} As the dataset is sourced from 6 independent collections, cross-source duplicates are expected. Duplicate detection is performed using perceptual hashing with a 256-bit phash and a Hamming distance threshold of 0, meaning only bitwise-identical hashes are considered duplicates. This identified 5,827 exact duplicates across sources. Duplicate entries are not removed from the FAISS indices to ensure that index positions remain consistent with the metadata file. Instead, duplicates are filtered out at retrieval time. After NSFW filtering and deduplication, the usable dataset contains 9,703 unique clean memes.

\textbf{Russian Search Query Translation.} Query retrieval performance for Russian-language queries was improved by translating the search queries field of all 16,030 memes to Russian using GPT through an OpenAI-compatible API. The translated queries were encoded into a dedicated Russian FAISS index using bge-m3. This justifies keeping a separate Russian index, as shown by the language routing experiment below: routing Russian queries to Russian-language descriptions yields Hit@5 = 45\%, versus 37\% for cross-lingual search against English-language descriptions.

\label{sec:lang_exp}

To evaluate this, 100 translated captions were generated for the test memes and encoded with bge-m3. Table~\ref{tab:routing} presents the results.

\section*{Conclusion}
\addcontentsline{toc}{section}{Conclusion}

This report presents a VQA-enhanced multimodal meme retrieval system. A dataset of 16,030 memes (9,703 unique after deduplication) was collected from 6 sources and annotated with 10 structured VQA fields using gpt-5.4-mini-fast with vision. All search queries were additionally translated into Russian to support cross-lingual retrieval. Eight multilingual embedding models were compared, with bge-m3 selected as the production encoder due to balanced performance on both English and Russian data.

The retrieval pipeline combines an early-fusion mega-text index with late-fusion Reciprocal Rank Fusion across 3 FAISS indices, followed by Maximal Marginal Relevance post-processing for diversity. Perceptual hash deduplication filters near-duplicate results. The system is deployed as a production-ready Telegram bot supporting text, image, and hybrid search modes, automatic database updates, cluster-based index rotation, and paginated results.

Evaluation on 99 test memes with 495 queries per language demonstrates significant improvements over the initial baseline: EN Hit@5 increased from 32\% to 60.0\% and RU Hit@5 increased from 2\% to 57.0\%. A user-centric evaluation with three human raters and LLM-as-a-Judge on 100 natural search queries confirms acceptable relevance and effective diversity across both languages. End-to-end search latency averages under 40\,ms per query on consumer hardware. Future work includes expanding the test set with LLM-assisted annotation and automating meme collection through additional web sources.

During the development of this project, large language models were used as coding assistants for implementation tasks such as debugging, code optimization, and document formatting. Below are representative examples of prompts and responses.

\bigskip

\noindent\textbf{Prompt 1.} \textit{Model: Claude Sonnet (Anthropic, via Antigravity IDE)}

\begin{quote}
\small
\texttt{what is the best multilingual sentence embedding model for semantic search if i need both english and russian? i'm comparing bge-m3, multilingual-e5-large, and labse}
\end{quote}

\noindent\textbf{Response} (abridged):
\begin{quote}
\small
For balanced EN+RU performance, bge-m3 is the strongest choice. It outputs 1024-dim normalized vectors, supports 100+ languages, and handles both dense and sparse retrieval. multilingual-e5-large scores higher on English benchmarks but drops significantly on Russian. LaBSE is optimized for translation pairs rather than semantic similarity. If your use case is search (not NLI), bge-m3 is the recommended default.
\end{quote}

\bigskip

\noindent\textbf{Prompt 2.} \textit{Model: Claude Sonnet (Anthropic, via Antigravity IDE)}

\begin{quote}
\small
\texttt{should i use IndexFlatIP or IndexFlatL2 in faiss}\\
\texttt{if my vectors are already l2-normalized?}
\end{quote}

\noindent\textbf{Response} (abridged):
\begin{quote}
\small
For L2-normalized vectors, IndexFlatIP (inner product) and IndexFlatL2 (Euclidean distance) produce equivalent rankings. IndexFlatIP is slightly more common in practice because cosine similarity equals inner product for unit vectors. Just make sure to also normalize your query vectors before calling \texttt{index.search()}, otherwise scores will be magnitude-dependent.
\end{quote}

\bigskip

\noindent\textbf{Prompt 3.} \textit{Model: Claude Opus (Anthropic)}

\begin{quote}
\small
\texttt{what is a good way to combine results from}\\
\texttt{multiple faiss indices with different relevance}\\
\texttt{signals? i have a text embedding index and a}\\
\texttt{keyword bm25 index}
\end{quote}

\noindent\textbf{Response} (abridged):
\begin{quote}
\small
Reciprocal Rank Fusion (RRF) is the standard approach. For each document, compute $1/(k + \text{rank})$ from each index and sum the scores. The constant $k$ is typically set to 60. RRF is score-agnostic, so it works across heterogeneous retrievers without normalization. For result diversity, apply Maximal Marginal Relevance (MMR) as a post-processing step with a cosine similarity threshold around 0.8.
\end{quote}
